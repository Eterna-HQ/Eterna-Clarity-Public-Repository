# Repository Governance

This repository contains deliberately selected public resources from Eterna Clarity. Public visibility does not make Eterna's private operating environment public by default.

## Release standard

A resource should be added here only when it is:

1. **Useful on its own** — it provides practical value independent of buying an Eterna product or service.
2. **Evidence-safe** — consequential factual, benchmark, or methodological claims have been checked against appropriate current sources.
3. **Publication-safe** — it contains no credentials, private customer information, restricted data, private filesystem details, or internal-only implementation material.
4. **Complete enough to use** — documentation, inputs, outputs, limitations, and dependencies are understandable for the intended audience.
5. **Versionable** — material changes can be tracked clearly over time.
6. **Deliberately released** — inclusion is an explicit public-release decision, not an automatic export from internal work.

## Repository boundaries

This repository may contain public frameworks, templates, checklists, schemas, taxonomies, methodologies, tools, and standards.

It is not a mirror of Eterna OS, private infrastructure, internal operating records, customer environments, credentials, or unfinished internal research.

## Website and GitHub roles

The Eterna Clarity website provides the polished human-facing explanation and canonical resource experience. GitHub provides inspectable source, version history, downloads, and implementation detail when openness improves a resource.

The two surfaces are complementary; neither requires a one-to-one copy of the other.

## Versioning and citations

Where a resource changes materially, its version or release history should make that change inspectable. References to a resource should prefer its canonical path and exact version when reproducibility matters.

## Licensing

There is currently no repository-wide license. Licensing may be assigned deliberately to individual resources or later standardized across appropriate resource classes. Do not infer that all resources share identical permissions unless an explicit license says so.
